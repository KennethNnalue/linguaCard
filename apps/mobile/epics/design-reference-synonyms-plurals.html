What's changing
Two upgrades to vocabulary cards. (1) "Related words" are replaced by AI-generated true synonyms, each with a translation and an expandable example sentence. (2) Every noun gets a structured plural form, generated at creation/import and surfaced on the detail page and in review — following the German-teaching principle of learning article + plural together with the word.

Related words → Synonyms: before & after
Why the change matters, using the real example from the current screenshots.
Before — stem matching

das Flugzeug → "Related Words"

Derived client-side: lowercase the word, take the first 4 characters as a "stem", then match other vault cards by substring with a length filter. Result is orthographic noise — and only ever words already in the user's vault.

dasHobby ✕ not a synonym
dasCafé ✕ not a synonym
dasBuch ✕ not a synonym
After — AI synonyms

das Flugzeug → "Synonyms"

Generated by the enrichment model and stored on the card. True meaning-equivalents, each with a translation and an example sentence the learner can expand — and they're independent of what's already in the vault.

dieMaschine ✓ "Die Maschine landet…"
derFlieger ✓ "Der Flieger startet…"
Design rationale & UX research
Decisions behind where each piece of data lives.
Article + plural, learned together

Every credible German resource gives the same advice: memorize der Tisch, die Tische as one unit, never the bare noun. So plural sits next to the headword on detail, and on the review back face — the recall surface where article + plural should be rehearsed as one.

Synonyms need context

Retention research and the strongest vocab apps pair each synonym with a translation and a sample sentence. A bare list teaches substitution without nuance; a synonym + example teaches when to use it. Each synonym is { word, article, translation, example }, expandable on tap.

Don't clutter the review card

The review card is a recall test. Plurals belong there (part of the word's identity); synonyms do not — they'd dilute the test. Synonyms live on the detail page and, compactly, in the Listen Deep Dive browsing surface.

Graceful absence

Many words have no good synonym, and non-nouns have no plural. Every surface hides the field cleanly when empty — no empty headers, no — noise. The model is told to return [] rather than invent weak synonyms.

Generate, don't burden

Manual entry gets a one-tap ✨ Auto-generate that fills translation, article, plural, example, and synonyms via the same enrichment path as import — so quality matches and users rarely hand-type synonyms.

Backwards compatible

New fields are optional (plural: string | null, synonyms: Synonym[] defaulting to []). Hundreds of existing cards keep working; an optional batch backfill fills them in later without overwriting anything.

Data model change
The single source of truth — libs/shared/domain/src/index.ts.
export interface Synonym {
  word: string;            // synonym headword, no article
  article: ArticleType | null;
  translation: string;     // native-language meaning
  example: string;         // target-language sentence using it
  exampleNative: string;   // translation of that sentence
}

export interface CardContent {
  front: string;
  back: string;
  article: ArticleType | null;
  gender: GenderType;
  plural: string | null;     // NEW — full plural w/ article: "die Flugzeuge"
  examples: ExampleSentence[];
  synonyms: Synonym[];          // NEW — true synonyms, defaults to []
  notes: string;
  audioAssetId: string | null;
  imageUrl: string | null;
  phonetic: string | null;
}
