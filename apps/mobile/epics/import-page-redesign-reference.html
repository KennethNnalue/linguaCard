AI Prompt — Full Text
This is the complete prompt that gets copied to the user's clipboard. It's derived from our WordEnrichPromptBuilder but simplified for human consumption. The prompt outputs CSV that matches our parser's expected column layout exactly.
Complete Prompt (copied to clipboard)
I have a list of German words I want to study. Create a CSV file with these exact column headers: front,back,article,plural,category,exampleTarget,exampleNative Column definitions: - front: English translation (e.g. "dog") - back: German word WITHOUT article (e.g. "Hund") - article: der, die, or das — leave empty for verbs, adjectives, phrases - plural: Full plural with article (e.g. "die Hunde") — leave empty for verbs - category: One of: Food, Travel, Home, Work, People, Nature, Transport, Shopping, Health, Other - exampleTarget: A natural German sentence using the word - exampleNative: English translation of that sentence Rules: - The "back" column must NEVER include the article — that goes in the "article" column only - Wrap any field that contains commas in double quotes - Include the header row as the first line - Use correct German grammar in all sentences Here are my German words: [PASTE YOUR WORDS HERE — one per line] Output ONLY the CSV with headers. No markdown fences. No explanations.
Why not include synonyms in the prompt? The synonym columns (synWord, synArticle, etc.) add significant complexity to the prompt and most AI tools struggle with the 3×5 repeating column structure. For the best user experience, we keep the prompt focused on the 7 core columns. Synonyms can be backfilled via our enrichment pipeline later.
Prompt shown in the UI (abbreviated)
// This shorter version is shown in the phone UI card. // The full version above is what actually gets copied to clipboard. Create German vocabulary flashcards as a CSV. Columns: front,back,article,plural,category,exampleTarget,exampleNative • front = English translation • back = German word (no article) • article = der/die/das or empty • plural = full form (e.g. die Hunde) • category = Food, Travel, Home, Work, People, Nature, Transport, Shopping, Health, Other • exampleTarget = German sentence with the word • exampleNative = English translation of the sentence [PASTE YOUR WORDS HERE] Output ONLY the CSV. No explanations.
Two versions of the prompt: The UI card shows a shorter preview for scannability. The clipboard copy contains the full, detailed version with rules and examples to maximize AI output quality.
CSV output mapping to parser
// CsvParserService column indices (0-indexed): Column 0: front → ParsedImportRow.front Column 1: back → ParsedImportRow.back Column 2: article → ParsedImportRow.article (der/die/das/null) Column 3: plural → ParsedImportRow.plural Column 4: category → ParsedImportRow.categoryId (matched by name) Column 5: exampleTarget → ParsedImportRow.exampleTarget Column 6: exampleNative → ParsedImportRow.exampleNative // Synonym columns (7+) are intentionally omitted from the AI prompt. // These columns still work if the user provides them manually.
Import Format Comparison
Evaluating whether CSV is the best format, or if there's a simpler alternative for user-generated imports.
Format Options
Format User Effort Data Richness AI-friendly Implementation
Plain text list
One word per line		 ★★★ Easiest ★ Words only — needs server enrichment N/A — no AI needed New endpoint + "Paste Words" UI. Reuses enrichment pipeline.
CSV (7 columns)
Current format		 ★★ Needs AI help or template ★★★ Full card data ★★★ AI generates well Already implemented. Parser exists.
CSV (22 columns)
With 3× synonyms		 ★ Too complex ★★★ Everything including synonyms ★ AI struggles with structure Already implemented. Parser handles it.
JSON
Structured objects		 ★ Not user-friendly ★★★ Unlimited structure ★★★ AI generates easily Would need new parser + file picker support.
Recommendation: Keep CSV (7 columns) as the import format — it's already implemented, AI tools generate it well, and the prompt helper makes it accessible. For v2, add a "Paste Words" flow that sends plain text to the server enrichment pipeline (eliminating CSV friction entirely for casual users). The synonym columns are best handled by server-side backfill, not user-generated CSV.
Future Concept: Paste Words
The ultimate simplification — users type or paste German words directly, and our existing enrichment pipeline generates full flashcards server-side. No CSV, no AI prompt, no file downloads.
Architecture: How Paste Words would work
// User pastes a list of German words (one per line) Input: "Flugzeug\nSchmetterling\nKrankenhaus" // Client converts to RawExtractedWord[] (same type image-import uses) const rawWords: RawExtractedWord[] = lines.map(line => ({ back: line.trim(), })); // Call the EXISTING enrichment endpoint POST /import/enrich Body: { rawWords, targetLanguage: 'German', nativeLanguage: 'English', } // Returns ImageExtractedWord[] → same review page as image import → Navigate to /vault/import/image/review // Reuses the entire image-import review + card creation flow
Effort estimate: ~8 story points. One new page (text input + word list preview), one new endpoint call (reusing WordEnrichService), and navigation to the existing image-import review page. The enrichment pipeline, review page, and card creation logic are all reused.
