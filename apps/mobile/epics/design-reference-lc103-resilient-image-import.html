Two-Phase Import Flow
The import flow is split into Phase 1 (image vision — extract raw words) and Phase 2 (text enrichment — generate translations, examples, categories in batches of 10). Rate limits mid-Phase 2 produce a partial result — the user still gets their ready cards immediately, and the collection tracks pending words for later completion. Screens I01–I05 cover the full end-to-end import journey. I06–I07 cover the post-import incomplete collection experience.

Incomplete Collection Experience
After a partial import, the collection is saved with importStatus: 'incomplete' and pendingWords[] stored in the database. Two surfaces show the incomplete state: the collection detail page (I06, banner + "Complete" button + ghost placeholder rows) and the collections list (I07, amber dot indicator with pending count). Tapping "Complete" on I06 calls POST /import/complete/:collectionId and resumes Phase 2 enrichment for only the pending words.

Design Rationale & UX Decisions
Key decisions behind the two-phase import and incomplete collection experience.
I01 — Why a dedicated picker screen

Context: The existing import entry page (/vault/import) was extended in LC-088 to surface the image import button. Screen I01 is the dedicated /vault/import/image route after tapping that button.

The dashed-border dropzone mirrors the existing CSV import affordance, making the feature immediately discoverable. Tips are shown upfront because image quality directly affects extraction accuracy — preventing user frustration before it starts.

I02 — Phase 1 scan animation

The scan line animating over the image thumbnail is a functional metaphor — it tells the user the AI is reading text from the image, not just "thinking". This reduces perceived wait time and builds mental model.

The two-step progress indicator (Phase 1 active, Phase 2 grayed out) sets expectations: the user knows there are two steps, so they're not surprised when the screen transitions to a second phase instead of jumping straight to the review screen.

I03 — Batched progress with word chips

The word chip grid is the most important UX decision in the entire flow. Each chip turning green as its batch completes gives the user granular feedback — they can see their vocabulary accumulating in real time, not just a spinner.

The note "Processing 10 words at a time — your progress is saved after each batch" explicitly tells the user why they're seeing this progress, removing the black box. This manages expectations for the rate limit case — if the bar stops at 68%, the user already understands why.

I04 — Partial result is not an error

Critical design decision: Screen I04 uses amber (warning) rather than red (error) intentionally. 32 of 47 cards is a success, not a failure. The framing is "32 cards are ready now" not "import failed".

The CTA says "Add 32 cards to collection" — not "try again" or "retry". The user gets immediate value. The pending 15 become a background concern handled through the collection detail (I06), not a blocker on the happy path.

I05 — Review screen: partial import indicator

The review screen shows the "15 pending" badge inline in the image info row so users understand the incomplete state before confirming. The summary row surfaces the pending count as a distinct stat alongside selected and total.

Words with generated card data are shown as normal selectable rows. Pending words are not shown — they have no data yet. The CTA correctly says "Import 30 words" (the selected count), never referencing the pending words which can't be imported yet.

I06 — Incomplete banner design

The banner appears between the hero stats and the action buttons — directly in the user's scan path, impossible to miss. It uses the amber palette consistently with I03 and I04.

Ghost placeholder rows below the real word list visually represent the pending words. They are intentionally faint and show no content — this communicates "these slots exist but aren't filled yet" without being alarming. The section label "Pending (15) — tap Complete above" provides direct instruction.

The "Complete" button in the banner calls POST /import/complete/:collectionId. On success the banner disappears, the ghost rows are replaced by real cards, and the collection stat updates in place — no navigation required.

I07 — Amber dot: scannable at a glance

The amber dot next to the collection name is deliberately small (7px) and uses the amber palette that users have already seen in I03, I04, and I06 — creating visual consistency across the whole flow.

The amber border on the incomplete card provides a secondary signal so the collection is findable even when the list is long. The meta row shows "15 pending ⏳" in amber text as tertiary reinforcement.

Collections with importStatus: 'complete' (all CSV imports, completed image imports) show no dot — the indicator is additive only, never subtractive.
