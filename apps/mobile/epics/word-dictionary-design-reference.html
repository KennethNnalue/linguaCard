Global Word Dictionary & Admin Authoring
One canonical enriched lexicon · never enrich or voice a word twice · admin platform import
LC-WD01 → LC-WD17 · ~55 pts

The platform solved "generate once, reuse everywhere" — but only for audio

The word_audio registry already gives every word a single shared voice, content-addressed and cross-user. Enrichment never got the same treatment: every import and story call re-enriches words the platform already knows, and image import even enriches before it deduplicates — paying tokens for words it then discards. This epic adds the missing half: a global word dictionary every entry point checks before calling AI, linked to the audio registry so a word carries both its meaning and its voice, made once and shared by all users. Plus the admin flow to import platform collections and stories through that same dictionary.

ADR-1 · ADR-3 · The architecture
The dictionary is the hub every entry point passes through
Imports, stories, the add-word sheet, and admin authoring all ask the dictionary first. A hit returns enriched data with zero AI tokens; only a true miss reaches the model, which enriches exactly once and links the word to its single audio record. Mirrors the proven word_audio design (semantic-cache / content-addressable pattern).

LC-WD13 · Run manually, import the result
The platform-story generation prompt
The admin pastes this into an AI tool to author a canonical platform story from a collection's words, then imports the JSON via POST /admin/platform-stories/import. Firm, concrete, with correct/incorrect examples per our prompt-engineering standard. Keywords import through the dictionary (reuse, not re-enrich).
ROLE: You are a German-language curriculum writer producing a CANONICAL platform story for a vocabulary app. It will be shown to MANY learners — correct, natural, tightly scoped. TARGET CEFR LEVEL: {{LEVEL}} // A1, A2, B1, B2, C1 TOPIC: {{TOPIC}} WORD LIST (use these exact words; don't invent vocabulary beyond this level): {{WORD_LIST}} // "der Apfel = apple", "bestellen = to order", … HARD RULES 1. Use AT LEAST 80% of the WORD LIST, each in a NATURAL everyday context. ✅ "Im Café bestellt Lena einen Apfelsaft und ein Stück Kuchen." ❌ "Der Apfel ist ein Apfel. Ich bestelle bestellen." (forced) 2. Stay strictly at CEFR {{LEVEL}}. A1/A2: short clauses, present + simple past, no subjunctive/passive. Don't exceed the level to sound impressive. 3. Correct grammatical form — right article, case, conjugation. ✅ "Sie gibt dem Kellner das Trinkgeld." (dative) ❌ "Sie gibt der Kellner die Trinkgeld." 4. Complete arc, 8–16 sentences (short) / 16–28 (medium). Natural dialogue where it fits. 5. English translation for every sentence and the title. 6. Don't pad to hit the quota — only natural usage counts. OUTPUT — valid JSON only, no fences, no commentary: { "title": "…", "titleTranslation": "…", "level": "{{LEVEL}}", "topic": "{{TOPIC}}", "sentences": [ { "german": "…", "english": "…", "wordsUsed": ["Apfel","bestellen"] } ], "keywords": [ { "germanBase": "Apfel", "article": "der", "english": "apple", "wordType": "noun", "level": "A1" } ] }

UNIQUE (lemmaKey, targetLang, nativeLang) — "enriched twice" impossible at the DB level. No userId: shared by all users (ADR-2).

Card linkage — copy, don't reference

Cards copy the dictionary entry into their editable content on create, and store dictionaryWordId for audio reuse + provenance. Editing a card never mutates shared data; audio resolves via the link, not a re-keyed lookup (ADR-4).

One normalizer

normalizeLemma(text, article) keys audio, dictionary, vault dedup, and within-batch dedup. "der Apfel", "Der Apfel", "der apfel." all collapse to one key — the precondition for every reuse claim (ADR-5).

Two dedup questions, one surface

In my vault? → per-user WordDedupService (kept) → amber, deselected.

Known to platform? → dictionary.lookup (new) → reuse toggle, on by default. The user confirms reuse or forces fresh enrichment (ADR-6).

Reused from the audio epic — not rebuilt

word_audio, WordAudioService.resolve, inflight dedup, R2 storage, the lookup endpoint — all already shipped. The dictionary links to them; it does not duplicate them.

Ticket prefix — LC-WD

Cross-cutting infrastructure uses a letter sub-prefix (WA audio, AP persistence). This epic is WD — consumed by many features, sitting alongside the feature hundred-blocks rather than after them (ADR-7).
