1 · Current State Audit
What already works, what's broken, and what doesn't exist yet. Read this before writing any code.
Your question: What is the difference between pronunciation/ and word-audio/ in R2?
You guessed right. Here's what each R2 prefix holds and what it means:
⚠ pronunciation/{cardId}.wav Legacy
The old format. One file per card, keyed by cardId. If two cards have the same German word, two separate files exist. These were generated on-demand when a user first tapped 🔊.

These are being migrated away from by the existing LC-WA epic scripts.
✅ word-audio/{hash}.wav Target
The new format. One file per unique German word text, keyed by SHA-256 hash of the normalized text. "der Hund" is stored once regardless of how many cards reference it.

This is what the WordAudioService (NestJS + Angular) already produces.
📖 stories/{storyId}.wav Works
Full story narration audio — long-form TTS, different beast entirely. One file per story, includes karaoke timestamps. Generated by StoryAudioService.

Not affected by this epic.

⚠ What's still broken / missing — the real work
Audio not persisted on device after refresh
WordAudioService.play() uses the autoplay-policy workaround (falls back to Web Speech on cache miss rather than awaiting API). The result: device cache never gets populated on first play. Audio is re-generated from the API every session refresh because the Capacitor Filesystem write only happens when resolveAndCache() is explicitly called — which no flow currently does eagerly.
No pre-generation on collection import/creation
After a collection is imported (CSV or image), no audio is pre-generated. Users hit the generate-on-demand flow every time they first interact with a word. CardStore.create() and the bulk import endpoint don't trigger WordAudioService.batchResolve() after card creation.
CSV import has no duplicate detection
import-review.page.ts (CSV flow) has zero duplicate checking. The image import already has _checkVaultDuplicates(). The CSV import needs the same treatment. The "Add anyway → use existing card reference" flow is also unimplemented everywhere.
Client-side dedup lookup uses API call, not local store
Current duplicate checks POST to /cards/check-duplicates on every import. Since CardStore already holds all the user's cards in memory, this API call is wasteful. A client-side Map lookup using a normalized key is O(1) and avoids network latency entirely.
Add-word sheet has no duplicate warning
add-word-sheet.component.ts has zero duplicate detection. No warning fires when a user manually types a word that already exists in their vault.

Client-Side Dedup Algorithm
No API call needed. CardStore already has all cards in memory. Build a normalized lookup Map on first use, then O(1) checks forever.
// shared/dedup/card-dedup.service.ts buildIndex(cards: Card[]): Map<string, Card> { const map = new Map<string, Card>(); for (const card of cards) { const key = normalize( card.content.article, card.content.back ); // First occurrence wins — no double-storing if (!map.has(key)) map.set(key, card); } return map; } normalize(article: string|null, back: string): string { const w = back.toLowerCase().trim(); const a = article?.toLowerCase().trim() ?? ''; return a ? `${a} ${w}` : w; }
Index built once when CardStore loads. Checked instantly on import review and add-word sheet. Zero API calls.

Phase A — Device Cache Fix
LC-AP01 Fix device cache write: download and persist audio after first API resolution
3 pts To do
Phase A · Depends on: AP02
Root cause: WordAudioService.play() correctly falls back to Web Speech on autoplay-policy grounds (you can't await an async call and then play audio — the browser blocks it). But the background resolution that follows never saves the resolved URL to the Capacitor Filesystem. On next session, _urlMap is empty and the device cache is empty, so we hit the API again.
Files to modify
FileChange
shared/audio/word-audio.service.tsAfter API resolution returns audioUrl, call AiAudioCacheService.saveFromUrl() in background
shared/audio/word-audio.service.tsOn startup (service init), warm _urlMap from Capacitor Filesystem by scanning cache dir
Key implementation pattern
// word-audio.service.ts — after API returns audioUrl private async resolveAndCacheInBackground( text: string, language: string, cacheKey: string ): Promise<void> { try { // 1. Check device cache (may have been populated by a concurrent call) const deviceCached = await this.cache.getFromCache(cacheKey); if (deviceCached) { this._urlMap.set(cacheKey, deviceCached); return; } // 2. Fetch from API (backend resolves or generates) const resp = await this.api.resolve(text, language); if (!resp.wordAudio.audioUrl) return; // still generating // 3. Download to device and update in-memory map const localUrl = await this.cache.saveFromUrl( cacheKey, resp.wordAudio.audioUrl ); this._urlMap.set(cacheKey, localUrl ?? resp.wordAudio.audioUrl); this.audioReadiness.markReady(cacheKey); // notify AP03 store } catch (err) { // Non-fatal — next play() will retry console.warn('Background audio cache failed', err); } }
Acceptance criteria
  • After first play of a word (which uses Web Speech fallback), audio is downloaded to device in background
  • Second session: playing the same word hits Capacitor Filesystem immediately, no API call
  • Third play same session: hits _urlMap in-memory, no filesystem read
  • Background download failure does not crash, logs warning, retried on next play
  • On native platform only (web platform skips Capacitor Filesystem per existing isNative guard)
  • Unit test: verify saveFromUrl() is called after successful API resolution

async saveFromUrl( cacheKey: string, remoteUrl: string, ext: 'wav' | 'mp3' = 'wav' ): Promise<string | null> { if (!this.isNative) return remoteUrl; // web: stream directly const path = `${this.CACHE_DIR}/${cacheKey}.${ext}`; await Filesystem.mkdir({ path: this.CACHE_DIR, directory: Directory.Data, recursive: true }); await Filesystem.downloadFile({ path, url: remoteUrl, directory: Directory.Data }); const result = await Filesystem.getUri({ path, directory: Directory.Data }); return Capacitor.convertFileSrc(result.uri); }

Phase B — Pre-generation on Import
LC-AP05 CollectionAudioPrefetchService: batch-resolve + device-persist all words in a collection
3 ptsTo do
Phase B · Depends on: AP02, AP03
The core service for Phase B. Given a list of cards (from an imported collection), it batches all word texts, calls the backend batch-resolve endpoint, then downloads and persists each returned audio URL to device storage. This runs entirely in the background — the import confirmation UX does not wait for it.
FilePurpose
shared/audio/collection-audio-prefetch.service.tsNew service: prefetchCollection(cards: Card[])
@Injectable({ providedIn: 'root' }) export class CollectionAudioPrefetchService { private readonly api = inject(WordAudioApiService); private readonly cache = inject(AiAudioCacheService); private readonly readiness = inject(AudioReadinessStore); /** * Fire-and-forget. Do NOT await this from import flows. * Caller continues; audio arrives in background. */ prefetchCollection(cards: Card[]): void { this._run(cards).catch(err => console.warn('Audio prefetch failed:', err) ); } private async _run(cards: Card[]): Promise<void> { const words = cards.map(c => ({ text: (c.content.article ? `${c.content.article} ` : '') + c.content.back, language: 'de-DE', })); // Mark all as pending immediately words.forEach(w => { const key = this._cacheKey(w.text, w.language); this.readiness.markPending(key); }); // Batch resolve (50 words per call max) const CHUNK = 50; for (let i = 0; i < words.length; i += CHUNK) { const chunk = words.slice(i, i + CHUNK); const resp = await this.api.batchResolve(chunk); for (const item of resp.results) { if (!item.wordAudio.audioUrl) continue; const key = this._cacheKey(item.wordAudio.displayText, item.wordAudio.language); try { await this.cache.saveFromUrl(key, item.wordAudio.audioUrl); this.readiness.markReady(key); } catch { this.readiness.markFailed(key); } } } } }
  • prefetchCollection() is fire-and-forget — does not block caller
  • Words chunked into batches of 50 to respect API rate limit
  • Each word's status updated in AudioReadinessStore as it completes
  • Words already in device cache are skipped (getFromCache check before saveFromUrl)
  • On WiFi only for native platform (reuse Network.getStatus() guard from StoryAudioPrefetchService)
  • Failure of individual word does not stop rest of batch
  • Integration test: 10-word collection → 10 files in Capacitor Filesystem after prefetch completes

Phase C — Client-side Dedup
LC-AP10 CardDedupService: normalized in-memory index from CardStore
2 ptsTo do
Phase C · No dependencies
All the user's cards live in CardStore in memory. A normalized lookup index eliminates every API call for duplicate checking. The index is a computed signal — it auto-rebuilds when cards change.
FilePurpose
shared/dedup/card-dedup.service.tsIndex builder + lookup. Pure synchronous — no async, no HTTP.
@Injectable({ providedIn: 'root' }) export class CardDedupService { private readonly cardStore = inject(CardStore); // Computed: rebuilds automatically when cards change readonly index = computed(() => { const map = new Map<string, Card>(); for (const card of this.cardStore.cards()) { const key = this.normalizeKey(card.content.article, card.content.back); if (!map.has(key)) map.set(key, card); } return map; }); /** O(1) lookup. Returns existing card or null. */ check(article: string | null, back: string): Card | null { return this.index().get(this.normalizeKey(article, back)) ?? null; } /** Batch check — for import review rows */ checkBatch(words: {back: string; article?: string | null}[]): (Card | null)[] { const idx = this.index(); // read once — O(n) not O(n²) return words.map(w => idx.get(this.normalizeKey(w.article ?? null, w.back)) ?? null ); } private normalizeKey(article: string | null | undefined, back: string): string { const w = back.toLowerCase().trim(); const a = article?.toLowerCase().trim() ?? ''; return a ? `${a} ${w}` : w; } }
  • index is a computed signal — rebuilds when CardStore.cards() changes
  • check() and checkBatch() are synchronous, zero async
  • Normalization matches backend: lowercase, trimmed, article+space+word or word-only
  • "der Hund" ≠ "die Hund" (article is part of the key)
  • checkBatch() reads index once — O(n) not O(n²) for n-word imports
  • Performance test: 1000-card vault + 50-word import batch completes in < 5ms

7 · Risk Register
Known risks and mitigations. Review before starting each phase.
RiskLikelihoodImpactMitigation
Autoplay-policy blocks Audio.play() after background cache resolves High Medium Background cache write is separate from play(). First play still uses Web Speech. Cached audio used on next tap (still within gesture context).
WiFi-only guard makes pre-generation invisible to users on cellular Medium Low On cellular: audio generates on-demand as before. Progress bar simply doesn't appear. Users on cellular aren't worse off than today.
CardDedupService.index computed signal rebuilds on every card change during import Medium Low checkBatch() reads the signal once before the loop. Import creates cards sequentially, not in parallel. Index rebuild is O(n) but rare — not O(n) per word checked.
TTS API rate limit hit during batch pre-generation for large collections Medium Medium BatchResolve respects 5-concurrent backend limit. Rate-limited words get status 'failed' with retry on next CollectionAudioPrefetchService call. Google Cloud TTS (LC-114) has much higher limits than Gemini.
Duplicate card normalization mismatch between client and server Low High CardDedupService.normalizeKey() must exactly match WordDedupService.normalizeWord() — same lowercase+trim+article logic. Share a pure function from shared/domain if possible.
Capacitor Filesystem fills up on low-storage devices Low Medium AudioCacheEvictionService already exists for stories. Extend it to cover word audio. LRU eviction on least-recently-played words if total exceeds threshold (e.g. 100MB).
