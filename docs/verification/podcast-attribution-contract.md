# Podcast attribution and rollout contract

The API stores each issued exposure against its authenticated user and recording version. Impressions are separate from selections. The server copies placement, policy, discovery level, language pair and cohort from that exposure; arbitrary client metadata never establishes attribution. Selection establishes a journey. Preview records both selection and preview. Review transitions mark that selected journey as assisted. Actual audio play establishes its start. Progress requires that start before receiving attributed credit. Plain browsing remains unattributed; progress and listening still work with older clients lacking journey fields.

One completion and one meaningful milestone remain authoritative for an account/episode/audio version, with existing unique-range and reward deduplication. Journey/local-date ranges are additional analysis evidence. Replay starts a fresh journey; resume retains its originating selection. A replacement recording cannot reuse the old start or exposure. Account changes clear in-memory context; durable context is scoped by user and episode/version, and language changes invalidate attribution. Same-device continuation is supported; cross-device playback origins are outside this delivery.

The weekly primary metric is committed reviewers (at least one accepted review that local calendar week) listening meaningfully on at least two distinct local days. Meaningful means 30 seconds of unique played audio per journey/day, or the full audio duration if shorter. Completion remains 70% unique listening plus explicit completion request and is reported separately. Daily evidence uses server receipt time in the configured timezone, falling back to UTC. Delayed offline progress can shift dates; client discovery telemetry is best effort and may be lost. Do not compare cohorts until instrumentation coverage and this limitation are acceptable. Existing legacy milestones cannot reconstruct repeat listening days; the pre-instrumentation primary is unknown, not zero.

Independent API switches: PODCAST_RECOMMENDATIONS_HOME_ENABLED, PODCAST_RECOMMENDATIONS_REVIEW_SUMMARY_ENABLED, PODCAST_RECOMMENDATIONS_LIBRARY_ENABLED. Set false to disable one surface while catalogue/review remain usable. PODCAST_RECOMMENDATION_EXPERIMENT_VERSION defaults to vocabulary-v2-baseline, retaining the already-enabled experience; this is instrumentation, not a claim of an experiment. PODCAST_RECOMMENDATION_PERCENT defaults to 100. Optional PODCAST_RECOMMENDATION_INTERNAL_USER_IDS limits first enrollment to internal accounts. Assignment is hashed by account/version and persisted separately with cascading account deletion; later percentage changes cannot move enrolled accounts. Use a new explicit experiment version for an actual cohort experiment. Configure internal enrollment before enrolling production accounts if an internal-only launch is intended.

Exposure/event records follow existing podcast event deletion and retention conventions, including cascading account/episode deletion. No raw vocabulary text enters journey metadata. Assignment records survive episode deletion. No consent purpose is expanded beyond the existing first-party discovery telemetry; review existing product consent/retention configuration before an experiment.

Reports are reproducible in podcast-funnel-report.sql. Legacy or rejected contexts are grouped as unattributed; absence of an assignment is unassigned. Report direct/assisted, mature seven-day return and incomplete observation windows. Guardrails require separately measuring review-sync failures, playback errors and startup latency; a funnel alone is insufficient to authorize experiment expansion.
